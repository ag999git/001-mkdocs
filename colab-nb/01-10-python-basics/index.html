    Chapter 1: Python Basics 1¶

    Companion notebook for the book¶

    This notebook holds the code examples of Chapter 1. You do not need to type them. Just run them, read the explanations, and then change the code to see what happens. Changing code and watching the result is the fastest way to learn.

    How this notebook is arranged¶

    • Each code example from the book is in its own code cell. The code is the same as the printed code.
    • Before every example there is a text cell. It tells you what the code does, how it does it, why it matters, and what you should learn from it.
    • Some examples also have a text cell after them. Its heading starts with "Notes on Example" and the example number, so you always know which code cell it talks about.
    • A short "Beyond the Book" section at the end adds a few extra ideas. You can skip it on the first reading.

    How to run the code¶

    1. Click inside a code cell.
    2. Press Shift + Enter, or click the round Run button on the left of the cell.
    3. The result appears just below the cell.

    Run the cells from top to bottom. Some later cells use variables made by earlier cells.

    Two cells in this notebook are meant to fail with an error (Example 21 and the last cell of "Beyond the Book"). This is on purpose, so you can see what the error looks like. If you use Runtime > Run all and it stops at such a cell, click the next cell and choose Runtime > Run after.

    How to read the flowcharts¶

    The steps in each flowchart are numbered: they go 1, 2, 3 and so on. When the flow splits into two paths, one path uses the letter A (4A, 5A ...) and the other uses the letter B (4B, 5B ...). If the two paths join again, the numbering goes back to plain numbers.

    Background: how Python runs your code (Sections 1.2 and 1.3)¶

    There is no code in these sections, but one idea is needed for everything that follows.

    A computer cannot run Python text directly. Some program has to turn your code into actions. There are two ways to do this.

    • Compiler: reads the whole program first, translates all of it into a new file (object code or an executable), and only then is that file run. C++ works this way.
    • Interpreter: reads your program a little at a time and runs each part straight away. There is no separate translated file for you to manage. Python works this way.

    Path A is an interpreted language like Python. Path B is a compiled language like C++.

    Because Python is interpreted, you can use it in two ways:

    Interactive mode (command line) Script mode (.py file)
    How you use it Type one line, press Enter, see the result at once Write many lines in a file, save it, then run the whole file
    Good for Quick tests, trying out an idea, using Python as a calculator Real programs you want to keep, share and run again
    Is your code saved? No Yes

    A notebook like this one sits in between. Each cell can be run on its own, like interactive mode. But all the cells are saved in one file, like a script.

    Section 1.8: Using Python as a calculator¶

    The book shows four small calculations typed into a Jupyter Notebook (Figure 1.4). Examples 1 to 4 below are the same four cells.

    In each cell, Python works out the expression and shows the answer below the cell. You do not need print() here. A notebook, like the interactive shell, automatically shows the value of the last line of a cell.

    The four operators used here are:

    Operator Meaning Example Result
    + Addition 2 + 4 6
    * Multiplication 2 * 4 8
    ** Power (raise to) 2 ** 4 16
    / Division 2 / 4 0.5

    Subtraction (-) works the same way. You can also use round brackets ( ) to group parts of an expression, just as in school maths.

    Example 1: Addition, and your first comment¶

    What it does: adds 2 and 4 and shows 6.

    How it does it:

    • Line 1 starts with #. Everything after a # up to the end of that line is a comment. Python skips it completely.
    • Line 2 is 2+4. Python works out the sum. The part # Addition is again a comment, so Python ignores it.
    • Because 2+4 is the last line of the cell, the notebook shows its value.

    Why: comments let you leave notes for people who read your code. Python does not read them at all.

    Learning points:

    • A comment starts with # and runs to the end of the line.
    • A comment can take a full line (line 1) or sit at the end of a line of code (line 2).
    • In a notebook, the value of the last line is shown on its own.
    # Note comments in Python begin with # (hash) and are ignored by the interpreter
2+4# Addition

    6

    Example 2: Multiplication¶

    What it does: multiplies 2 by 4 and shows 8.

    How: Python uses * (the star, or asterisk) for multiplication. It does not use x, because x is a letter and can be a variable name.

    Learning point: the multiplication sign in Python is *.

    2*4# Multiplication

    8

    Example 3: Power¶

    What it does: works out 2 raised to the power 4, which is 2 x 2 x 2 x 2 = 16.

    How: two stars ** mean "raise to the power of". The number on the left is the base. The number on the right is the power.

    Learning point: ** is the power operator. Be careful: 2*4 is 8, but 2**4 is 16. One extra star changes the answer.

    2**4# 2 raised to power 4

    16

    Example 4: Division¶

    What it does: divides 2 by 4 and shows 0.5.

    How: a single slash / means division. In Python 3, / always gives a decimal answer (a float), even when both numbers are whole numbers.

    Learning point: the result of / is always a float.

    2/4# 2 divided by 4

    0.5

    Notes on Example 4 (and Examples 1 to 3)¶

    1. Division in Python is not the same as in C. In C or C++, dividing two whole numbers throws away the decimal part, so 2/4 gives 0. Python 3 does not do this. It keeps the decimal part.

    Expression Result in Python 3 Type of the result
    2/4 0.5 float
    4/2 2.0 float (not 2)
    7//2 3 int (// drops the decimal part)
    7%2 1 int (% gives the remainder)

    You will meet // and % in the chapter on operators. Try them now if you like: add a new cell and type 7//2.

    2. Spaces in expressions. 2+4# Addition works, but it is a little squeezed. The Python style guide (PEP 8, see Example 14) suggests spaces around operators and two spaces before an end-of-line comment:

    2 + 4  # Addition

    Both versions give exactly the same result. Spacing only makes code easier to read.

    3. Try it yourself. Change the numbers in Examples 1 to 4 and run the cells again. Then try (2 + 4) * 3 and 2 + 4 * 3. Why are the answers different?

    Section 1.9: Using the print() function¶

    Example 5: Printing text and a result together¶

    What it does: prints a piece of text followed by the answer to 2+2:

    The result of 2 + 2 is:-&gt; 4

    How it does it:

    • print is a built-in function. To call (use) a function, you write its name followed by round brackets ( ).
    • Inside the brackets you give the things you want printed. These are called arguments. Here there are two, separated by a comma:
    • "The result of 2 + 2 is:-&gt;" is text inside double quotes. Text in quotes is called a string. It is printed exactly as it is.
    • 2+2 is not in quotes, so Python works it out first and gets 4.
    • print() puts one space between its arguments and moves to a new line at the end.

    Why: in a script (a .py file), Python does not show values on its own the way a notebook does. print() is how a program shows results to the user.

    Learning points:

    • Anything inside quotes is printed as it is. "2 + 2" inside the string stays as the text 2 + 2.
    • Anything outside quotes is worked out first. 2+2 becomes 4.
    • Double quotes " " and single quotes ' ' both make strings.
    • Commas separate the arguments, and print() adds a space between them.

    Signature of print() (the full list of what it accepts):

    print(*objects, sep=' ', end='\n', file=None, flush=False)
    Parameter What it means Default
    *objects Any number of values to print, separated by commas nothing (prints an empty line)
    sep What to put between the values one space ' '
    end What to put after the last value a new line '\n'
    file Where to send the output the screen
    flush Send the output out at once False

    For now you only need *objects. The "Beyond the Book" section shows sep and end.

    print("The result of 2 + 2 is:-&gt;", 2+2 )

    The result of 2 + 2 is:-> 4

    Section 1.10: Running Python from a file (a script)¶

    Example 6: The one-line script hello.py¶

    What it does: prints the message Hello from a Python script!.

    How it is meant to be used: in the book, this line is saved in a file named hello.py. The file is then run from a terminal (command prompt) by typing:

    python hello.py

    On some computers (mostly macOS and Linux) the command is python3 hello.py.

    Here, in the notebook, we simply run the line in a cell. The output is the same.

    Why: a script is saved. You can run it again tomorrow, share it with a friend, or make it longer. Lines typed in the interactive shell are lost when you close it.

    Learning points:

    • Any file whose name ends in .py is a Python script.
    • A script is run as a whole, from the first line to the last.
    • In a script, you must use print() to see anything. A script does not show values automatically.

    Want to create and run a real hello.py file inside Colab? See "Beyond the Book", Extra 1.

    print("Hello from a Python script!")

    Hello from a Python script!

    Notes on Example 6¶

    Why use a script? Use a script when:

    • you want to keep your code,
    • the program is long,
    • you want to use functions, loops and modules,
    • someone else needs to run your program,
    • you want the computer to run it on its own, for example at a set time every day.

    Shell or script: a quick comparison

    Feature Python shell (command line) Python script (.py file)
    Saves your code No Yes
    Good for testing a line or two Yes Not ideal
    Suitable for full programs No Yes
    Can be run again later No Yes

    Section 1.11: Comments¶

    Python has two ways to write notes inside code:

    Hash # Triple quotes """...""" or '''...'''
    What it really is A true comment A string (text value)
    What Python does with it Skips it completely Creates the string, then throws it away if it is not used
    Covers From # to the end of that line As many lines as you like
    Main use Explaining how the code works, line by line Docstrings: describing what a function, class or module does and how to use it
    Read by People reading the code People and tools that build documentation (like help())

    Example 7: A comment over two lines using #¶

    What it does: nothing that you can see. Both lines are comments, so Python skips them. The cell runs without any output.

    How: a # comment only covers one line. To write a note that goes over two lines, you put a # at the start of each line.

    Why: this is the normal way to write a longer note in Python code.

    Learning points:

    • Every comment line needs its own #.
    • If you forget the # on the second line, Python will try to run that text as code and you will get an error. Try it: delete the # at the start of line 2 and run the cell.
    #This is a comment which extends over two lines..... this is line 1
#... This is line 2

    Example 8: Triple quotes used as a multi-line comment¶

    What it does: creates a string that spans three lines.

    How: text that starts with three quote marks (""" or ''') and ends with the same three quote marks can run over many lines. This is called a triple-quoted string.

    Why: people often use triple quotes as a multi-line comment, because Python does nothing harmful with a string that is not stored or used.

    Learning points:

    • Triple quotes make a real string. They are not a true comment.
    • When a triple-quoted string is the first line inside a function, class or module, it becomes a docstring. Tools such as help() read docstrings to build documentation.

    Run the cell and then read the note below it. The output may surprise you.

    """ Multi-line quote
... continues
.... ends"""

    ' Multi-line quote\n... continues\n.... ends'

    Notes on Example 8: why did the notebook show the text?¶

    A true comment (#) never produces output. But this cell did show something like:

    ' Multi-line quote\n... continues\n.... ends'

    The reason:

    1. The triple-quoted text is a string value, just like 2+4 is a number value.
    2. It is the last line of the cell. A notebook always shows the value of the last line.
    3. So the notebook shows the string. The \n marks show where each new line starts inside the string.

    In a .py script, nothing would be shown, because a script does not show values on its own. That is why triple-quoted strings behave like comments inside scripts.

    Remember: use # for comments. Keep triple quotes for docstrings.

    Section 1.11.1: Statements over many lines, and many statements on one line¶

    A statement is one instruction that Python can run. For example, x = 10 is an assignment statement. if, for and while statements are other kinds.

    Normally, a statement ends where the line ends. The next four examples show how to bend this rule, and when you should not.

    Way How it looks Needs a special character? Recommended?
    Explicit line continuation End the line with a backslash \ Yes, \ Only when there is no better way
    Implicit line continuation Keep the statement inside ( ), [ ] or { } No Yes, the preferred way
    Many statements on one line Separate them with semicolons ; Yes, ; No, avoid it
    One statement per line The normal way No Yes

    Example 9: Explicit line continuation with a backslash¶

    What it does: works out 2 + 3 + 4 and shows 9, even though the sum is split over two lines.

    How it does it:

    • The first three lines are comments. Python skips them.
    • Line 4 ends with a backslash \. This tells Python: "the statement is not finished, carry on to the next line."
    • Python joins line 4 and line 5 and reads them as 2 + 3 + 4.

    Why: it lets you break a very long statement into shorter lines that fit on the screen.

    Learning points:

    • The backslash must be the very last character on the line. Nothing can come after it: not a comment, and not even a space. Otherwise Python raises SyntaxError: unexpected character after line continuation character.
    • This is why the comment is written on separate lines above the code, and not after the \.

    Example 10: Implicit line continuation inside brackets¶

    What it does: adds 10 + 20 + 30 + 40 and prints 100.

    How it does it:

    1. Line 1 opens a round bracket (.
    2. As long as a bracket is open, Python knows the statement is not finished. It keeps reading the next lines.
    3. At the closing bracket ) on line 4, the statement is complete. Python adds the numbers and stores 100 in result.
    4. Line 5 prints result.

    Why: this is the clean, preferred way to split a long line. You do not need a backslash, and a stray space at the end of a line cannot break it.

    Learning points:

    • An open (, [ or { lets a statement continue over many lines.
    • Python waits for the matching closing bracket before it treats the statement as complete.
    • The indentation of lines 2 and 3 is only for looks. Inside brackets, Python does not care about it.

    30 + 40
)

    Example 11: Many statements on one line with semicolons¶

    What it does: stores 5 in a, stores 6 in b, and prints their sum 11. All three steps are on one line.

    How it does it: a semicolon ; separates statements. Python runs them one after the other, from left to right:

    1. a = 5 puts the value 5 in the variable a.
    2. b = 6 puts the value 6 in the variable b.
    3. print(a + b) adds them and prints 11.

    Why it is shown: so that you can recognise it when you see it. It is allowed, but it is not good practice.

    Learning point: a semicolon lets you put several statements on one line. Avoid it, because:

    • the code is harder to read,
    • errors are harder to find, since one line now holds several steps,
    • the logic is hidden, and mistakes are easier to miss.
    a = 5; b = 6; print(a + b)

    Why: the Python style guide (PEP 8) recommends one statement per line. Each line does one job, so the code is easy to read and to fix.

    Learning point: Examples 11 and 12 give the same result. The difference is only readability, and readability matters a lot when you or someone else comes back to the code later.

    Section 1.12: Indentation (no code in the book)¶

    Most languages such as C, C++ and Java use braces { } to mark a block of code. Python uses indentation instead: the spaces at the start of a line.

    • A block (for example, the body of an if or a function) starts when lines are indented.
    • The block ends at the first line that goes back to the earlier indentation.
    • Use 4 spaces per level. This is the common style.

    Sections 1.14 and 1.15: Identifiers, naming conventions and PEP 8¶

    An identifier is a name you give to something in your code: a variable, a function, a class, a module and so on.

    There are two kinds of naming rules:

    1. Legal rules. Python checks these. Break one and your code will not run.
    2. Conventions. Python does not check these. They are good habits that most Python programmers follow, mostly taken from PEP 8. Your code will run if you ignore them, but it will be harder for others to read.

    The legal rules¶

    Rule What it means Valid examples Invalid examples
    1. Allowed characters Only letters (a-z, A-Z), digits (0-9) and the underscore _ total_marks, value2, Student_Name hello-world, age@school
    2. First character Must be a letter or an underscore, never a digit value1, _count, name2 1value, 2ndNumber
    3. No keywords A keyword cannot be used as a name (none) for, while, class, break
    4. No special symbols Symbols like @, $, !, #, % and - are not allowed (none) first-name, price$, value#1
    5. Case matters Names that differ only in capital letters are different names student, Student, STUDENT are three separate names (none)

    A word of care about print: it is not a keyword in Python 3, so print = 10 is legal. But it is a very bad idea. After that line, print means 10, and print("Hi") stops working until you restart the notebook. The same goes for other built-in names such as list, str, type and id.

    PEP and PEP 8¶

    • PEP stands for Python Enhancement Proposal. A PEP is a document that proposes or describes something about Python.
    • PEP 8 is the official style guide for Python code. It covers naming, spacing, line length and more.

    The main naming conventions from PEP 8:

    What you are naming Style Example Avoid
    Variables snake_case: lowercase words joined by underscores student_age StudentAge, studentage
    Functions snake_case calculate_average CalculateAverage
    Constants (values that should not change) UPPER_CASE with underscores MAX_LIMIT maxlimit
    Classes PascalCase: each word starts with a capital, no underscores StudentRecord studentRecord, Attendance_Manager
    Names meant for use only inside a module A single leading underscore _internal_utility_function (no underscore, if it is meant to be internal)

    About camelCase: in camelCase the first word is lowercase and each later word starts with a capital, as in myAge. The capital letter looks like the hump of a camel. camelCase is common in Java and JavaScript. PEP 8 prefers snake_case (my_age) for variables and functions in Python.

    Also choose names that tell you what they hold. n = 10 is legal, but number_of_students = 10 explains itself.

    Section 1.16: Variables, literals, references and built-in types¶

    Some ideas in this part may feel new if you have never programmed before. Do not worry. Run each example, look at the output, and they will become clear.

    A variable is a tag, not a box¶

    A variable is a name that refers to a value (an object) stored in memory. The way this works is different in C++ and Python.

    • In C++, a variable is like a box. Each box is made for one kind of thing, just as a shoe box is made for shoes and a match box for matches. You must say what kind of box it is (int, float and so on) before you use it, and it keeps that kind for life.
    • In Python, a variable is like a price tag. The tag has no type of its own. You can take it off a shoe and tie it to a book. The object the tag is tied to has the type.
    Feature C++ (statically typed) Python (dynamically typed)
    What a variable is A box that holds a value A tag (label) tied to a value
    Must you declare the type? Yes (int, float, string ...) No
    Who has the type? The box (the variable) The object (the value)
    Can the same name later refer to a different type? No. An int variable cannot later hold a string Yes. The same name can point to any type
    Everyday picture Boxes for shoes, boxes for matches A price tag that can be tied to any item

    Static and dynamic typing. C++ is called statically typed, because the type of each variable is fixed when you write the code. Python is dynamically typed, because Python works out the type from the object at the moment the code runs.

    Python is also strongly typed. Dynamic does not mean careless. Python will not quietly mix types that do not fit together. For example, "5" + 5 gives an error instead of guessing what you meant. (See Beyond the Book, Extra 4.)

    Example 15: Two tags on one object, then one tag moves¶

    What it does: prints 2 and then 3.

    How it does it, step by step:

    1. x = 2: Python creates the object 2 and ties the tag x to it.
    2. y = x: Python does not copy the number. It ties a second tag, y, to the same object 2.
    3. y = 3: Python creates the object 3 and moves the tag y to it. Tag x is not touched. It is still on 2.
    4. print(x) prints 2, and print(y) prints 3.

    Why: many beginners expect x to change to 3 as well. It does not, because y = 3 only moves the tag y.

    Learning points:

    • = means "tie this name to that object". It does not mean "equal" as in maths.
    • y = x makes both names refer to the same object. It does not create a copy.
    • Giving a new value to one name never changes another name.

    x = 2  # x "points" to 2
y = x  # Now y also "points" to 2
y = 3  # Now y "points" to 3
print(x)  # x still "points" to 2, so it prints 2
print(y)  # y now "points" to 3, so it prints 3

    2
3

    • In Python every type is a class, which is why the output says class.

    Example 17: Casting a float to an int¶

    Casting (or type conversion) means making a new object of one type from an object of another type.

    What it does: turns the float 78.11 into the whole number 78, and prints the id (identity number) of each object.

    How it does it:

    1. my_float = 78.11 creates a float object and ties the tag my_float to it.
    2. id(my_float) gives the identity number of that float object.
    3. int(my_float) builds a new integer object from it. The decimal part .11 is dropped. The tag my_int is tied to this new object 78.
    4. print(my_int) prints 78.
    5. id(my_int) gives the identity of the integer object. It is a different number from step 2, because it is a different object.
    6. id(78) gives the same number as id(my_int). This shows that my_int points to the object 78.

    Why: in Python it is the object that is converted, not the name. int() does not change the float. It makes a new integer, and the float stays as it was. Numbers cannot be changed in place (they are immutable), so converting always creates a new object.

    Learning points:

    • int() drops the decimal part. It does not round: int(78.99) is also 78.
    • The original object (78.11) stays unchanged. Check it by printing my_float after the conversion.
    • The comments in the code mention myInt. They mean the variable my_int.

    Section 1.16.3: What happens in an assignment¶

    When you write x = 3, Python does three things:

    1. It creates the object 3 (an int) in memory.
    2. It creates the name x, if it does not exist yet. The name has no type of its own.
    3. It ties the name x to the object 3. This link is called a reference.

    If you now ask type(x), you get int. That is the type of the object x refers to, not a type of x itself.

    Section 1.16.4: Shared references¶

    When two or more names point to the same object, the object has a shared reference.

    Example 19: Two names, one object¶

    What it does: makes x and y point to the same object. There is no output.

    How it does it:

    1. x = 3: tag x is tied to the object 3.
    2. y = 2: tag y is tied to the object 2.
    3. y = x: tag y is moved to whatever x points to, which is the object 3.

    After line 3, both x and y refer to the object 3. The object 3 now has a shared reference.

    The object 2 has no tag left. Python notices this and frees that memory on its own. This is the automatic memory management (garbage collection) described in Section 1.3.2.

    Learning point: y = x makes y point to the object that x points to, here 3.

    x = 3
y = 2
y = x

    Example 20: Changing one name does not change the other¶

    Run Example 19 first. This cell needs x and y from it.

    What it does: adds 2 to x and prints 5 and 3.

    How it does it:

    1. Before this cell, x and y both point to 3.
    2. x = x + 2: Python first works out the right-hand side. It reads the value of x (3), adds 2, and creates a new object 5.
    3. The tag x is moved to the new object 5.
    4. The tag y is not touched. It still points to 3.
    5. So print(x) shows 5, and print(y) shows 3.

    Why: the object 3 is not changed into 5. Whole numbers cannot be changed in place (they are immutable). Python makes a new object and moves only the tag x. That is why y does not change.

    Learning points:

    • In x = x + 2, the right-hand side is worked out first, using the old value of x.
    • Changing what one name points to does not affect the other names.
    • Mutable objects (like lists) can behave differently with shared references. You will see this in the chapter on lists.

    Example 22: Looking at an object's identity with id()¶

    Every object in Python has three things:

    Property What it is How to see it
    Identity A number that is unique to the object while it exists id(obj)
    Type The kind of object, such as int or str type(obj)
    Value The data it holds, such as 10 print(obj)

    A name has one more property: its scope, meaning where in the program the name can be used. You will learn about scope in the chapter on functions.

    What the code does: prints the id of the object 10, then ties the name age to 10 and prints its id. Both ids are the same.

    How it does it:

    1. id(10) works out the id of 10, but the result is not printed. This is not the last line of the cell, so the notebook does not show it.
    2. print(id(10)) prints the id of the object 10.
    3. age = 10 ties the tag age to the object 10.
    4. print(id(age)) prints the id of the object that age points to. It is the same number as in step 2.

    Why: this shows that a variable is only a label for an object. age has no id of its own. id(age) gives the id of the object that age refers to.

    Learning points:

    • id() gives the identity of an object. In standard Python (CPython), this number is the object's address in memory.
    • If two names give the same id, they refer to the same object.
    • The same id here also comes from the small-number store described in the notes on Example 17: CPython keeps one shared object for each whole number from -5 to 256.
    • Your id numbers will not match the numbers in the comments. That is normal.

    Extra 3: Let Python check a name for you¶

    Two small tools help you check the naming rules from Section 1.14:

    Tool What it checks
    "some_name".isidentifier() Is the text built from legal characters, and does it not start with a digit?
    keyword.iskeyword("some_name") Is the text a keyword?

    A name can be used only if the first gives True and the second gives False.

    The code uses a for loop, which you will learn in the chapter on flow control. For now, read it as: "for each name in the list, check it and print the answer."

    The last line prints the soft keywords. These are words like match and case that act as keywords only in certain places. Elsewhere they can still be used as names, but it is better to avoid them.

    import keyword

names = ["total_marks", "_count", "1value", "first-name", "price$", "for", "Student"]

for name in names:
    usable = name.isidentifier() and not keyword.iskeyword(name)
    print(name, "-&gt;", usable)

print("Soft keywords:", keyword.softkwlist)

first-name -> False

for -> False

    Extra 4: Dynamic, but also strong (the last line gives an error on purpose)¶

    Python lets a name point to any type (dynamic typing). But it does not guess when you mix types that do not fit together (strong typing).

    • Line 1 turns the number 5 into the text "5" with str(), then joins two strings: 55.
    • Line 2 turns the text "5" into the number 5 with int(), then adds two numbers: 10.
    • Line 3 tries to add text and a number without converting. Python refuses and raises a TypeError.

    Some languages, such as JavaScript, would quietly turn "5" + 5 into "55". Python makes you say clearly what you want.

    print("5" + str(5))   # join two strings: 55
print(int("5") + 5)   # add two numbers: 10
print("5" + 5)        # TypeError: Python will not mix a str and an int

    55
10

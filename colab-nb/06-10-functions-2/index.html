    6.1 Passing of variables in a function call¶

    When you call a function and give it a variable, what does the function actually receive? Programming languages usually offer one of two answers:

    Method What the function gets Can the function change the caller's variable?
    Call by value A copy of the value No. It only changes its own copy
    Call by reference A link to the same variable Yes. Changes show up outside the function too

    Python does neither exactly. It uses pass by object reference (also called "call by sharing"): the parameter becomes a new name for the same object that the caller passed. What happens next depends on whether that object can be changed:

    • Immutable objects (int, float, str, tuple) cannot be changed in place. If the function "changes" one, Python makes a new object and moves only the local name. The caller sees no change. This looks like call by value.
    • Mutable objects (list, dict, set) can be changed in place. If the function changes the object, the caller sees the change, because both names point to the same object. This looks like call by reference.

    Back to the Table of Contents

    Example 1: An integer and a list passed to the same function¶

    What it does: passes an integer a = 5 and then a list c = [5, 4, 3] to process_data(). The function tries to change each one. The integer outside stays 5; the list outside becomes [5, 4, 3, 1].

    How it does it:

    1. isinstance(z, int) checks whether z is an integer. isinstance(z, list) checks for a list. (isinstance(object, type) returns True or False.)
    2. Integer case: at the start of the call, z and a have the same id, so they point to the same object 5. Then z = 4 makes a new object 4 and moves z to it. The id of z changes. a is not touched.
    3. List case: z and c have the same id. z.append(1) changes that one list in place. The id stays the same, and c sees the new item.

    Why: this is one of the most important ideas in Python. It explains why a function can change your list but not your number.

    Learning points:

    • Compare the ids in the output. In the integer case the id changes after z = 4. In the list case the id never changes.
    • The ids in the saved output will not match yours. What matters is which ids are equal.

    def process_data(z):
    """
    Shows how Python handles different object types during function call.
    """
    if isinstance(z, int):  # Check if z is an integer (immutable)
        print(f"--- Processing Integer (Immutable) ---")
        print(f"Initial internal z: {z} (ID: {id(z)})")

        # This does NOT change the original 'a'.
        # It creates a new local variable 'z' pointing to 4.
        z = 4
        print(f"Modified internal z: {z} (ID: {id(z)})")

    elif isinstance(z, list):  # Check if z is a list (mutable)
        print(f"\n--- Processing List (Mutable) ---")
        print(f"Initial internal z: {z} (ID: {id(z)})")

        # This modifies the object in-place.
        # Both 'c' and 'z' point to the same memory ID.
        z.append(1)
        print(f"Modified internal z: {z} (ID: {id(z)})")

# --- Main Execution ---

    6.2 Understanding a function call in Python¶

    • Each time a function is called, Python creates a new local scope for it (also called its execution context, or frame). It holds the parameters and local variables of that one call.
    • The local scope is thrown away as soon as the function finishes.
    • Think of it as a box inside a box: the caller is the outer box, and the running function is the inner box.
    • The function can read names from the outer scope. It can also change a mutable object that it was given.
    • But if it assigns to a parameter name (z = ...), it only moves its own local label. The caller's name is not affected.

    A note on tuples: a tuple is passed in exactly the same way as everything else, as a reference to the same object. It "acts like" call by value only because a tuple cannot be changed. There is no special rule for tuples.

    6.3 Pass by value compared with pass by reference: C++ and Python¶

    • In C++, a variable is like a box in memory with a fixed type. You declare the type in advance, and the box can only hold that type.
    • When calling a function in C++, you choose: pass a copy (call by value) or pass a reference to the original (call by reference, using &amp;).
    • In Python, a variable is a name tag tied to an object. The tag has no type; the object does. (Python is dynamically typed. It is also strongly typed: it will not quietly mix types, as Chapter 1 showed.)
    • Python has only one way to pass arguments: it always passes a reference to the object. There is no copying.

    Why does the original 5 not change, then? Because an integer object cannot be changed in place. When a function runs z = 4, Python does not overwrite the object 5. It finds or makes an object 4 and moves the local name z to it. The caller's name still points to 5.

    Why pass a reference even for a small integer? Two reasons: (1) uniformity: everything is an object, so Python uses the same rule for all of them; and (2) efficiency: passing a reference to a 100 MB string is instant, but copying it would be slow.

    Interning: Python also reuses small integers and short strings, so many names may point to the very same 5 object (see Chapter 3).

    Feature C++ Python
    How arguments are passed You choose: copy or reference Always a reference to the object
    Immutable object (int, str) Usually copied Reference passed; "changing" it makes a new object and moves the local name
    Mutable object (list, dict) Reference used explicitly (&amp;) Reference passed; the object can be changed in place

    6.4 The "reassignment" trap¶

    With a mutable object such as a list, there is one trap to watch for. Changing the list (z.append(...), z[0] = ...) affects the original. But reassigning the parameter with = just points the local name at a different object. The link to the original is broken, and the original is not changed.

    Example 2: Reassigning a list parameter¶

    What it does: passes my_list = [9, 9, 9] to a function that sets z = [1, 2, 3]. Afterwards my_list is still [9, 9, 9].

    How it does it:

    1. At the start of the call, z and my_list point to the same list.
    2. z = [1, 2, 3] creates a new list and moves z to it.
    3. The function ends and the new list is thrown away. my_list was never touched.

    Learning point: to change the caller's list from inside a function, change its contents (for example z[:] = [1, 2, 3] replaces all the items in place), or return the new list and let the caller assign it.

    def reassign_list(z):
    z = [1, 2, 3] # This creates a NEW list. It does NOT change the original.

my_list = [9, 9, 9]
reassign_list(my_list)
print(my_list) # Output is still [9, 9, 9]

    6.7 Default arguments (default values in the function definition)¶

    Sometimes a parameter has almost the same value every time, and only now and then does the caller want something different. For this, you can give the parameter a default value in the function definition.

    • If the call gives a value for that parameter, that value is used.
    • If the call leaves it out, the default is used.
    • Default values are written in the definition, never in the call.

    Problem with mutable default values¶

    A default value is worked out only once, when Python runs the def line. The resulting object is stored inside the function and reused by every call that leaves that argument out.

    • For an immutable default (a number, a string, None), this is harmless: nothing can change it.
    • For a mutable default (a list, a dictionary, a set), it is a trap: if one call changes the object, the change is still there in the next call.

    Back to the Table of Contents

    Example 6: The problem with a mutable default argument¶

    What it does: calls add_number_to_list(2) and then add_number_to_list(3). You might expect [2] and then [3], but the second call gives [2, 3].

    How it happens:

    1. When the def line runs, Python creates one empty list and stores it as the default for number_list.
    2. The first call appends 2 to that list: [2].
    3. The second call does not get a fresh list. It gets the same one, which already holds 2. Appending 3 gives [2, 3].

    Learning point: the comment on the last line says "Should be 3". It means the result you would expect is [3], a list holding only 3.

    # Example demonstrating the problem with mutable default arguments

    # Warning: Using mutable default argument (eg list) can lead to unexpected results
    # The default list is created only once when the function is defined, not each
    # time the function is called. So, if you modify this list (like appending a number)
    # it will affect all future calls that use the default list.

    # Add the number to the list
    number_list.append(number)

    # Return the modified list
    return number_list

    6.10 Passing arguments by name (keyword arguments)¶

    Positional arguments have a drawback: you must remember the order, and you cannot skip a parameter in the middle. (Some languages, such as Visual Basic, allow a call like f(a, , b, c), where the empty slot means "skip this one". Python does not.)

    Python solves this with keyword arguments: in the call you write parameter_name=value, so Python knows exactly which parameter each value is for.

    Keyword arguments let you:

    1. give the arguments in any order,
    2. make the call easier to read, and
    3. skip parameters in the middle, if they have default values.

    6.17 Explicit argument enforcement (/ and *)¶

    Since Python 3.8, two special markers in a function header control how arguments may be passed:

    1. / (slash): every parameter to its left is positional-only. It cannot be passed by name.
    2. * (star on its own): every parameter to its right is keyword-only. It must be passed by name.

    Symbol Name Effect In plain words

    6.18 Recursion¶

    • Recursion is a way of solving a problem by solving a smaller version of the same problem.
    • A function can call other functions. It can also call itself. A function that does so is recursive.
    • Each call works on a smaller piece of the problem, until the piece is so small that the answer is obvious.
    • Recursion must stop at some point. If it never stops, the calls pile up until Python gives up with a RecursionError ("maximum recursion depth exceeded"). By default Python allows about 1000 nested calls.

    Back to the Table of Contents

    Essential requirements for recursion¶

    Requirement Meaning
    Base case A simple case that is answered directly, without calling the function again
    Recursive case The function calls itself with a smaller version of the problem
    Progress toward the base case Each call must move closer to the base case

    If any of these is missing, the recursion never ends properly.

    A smaller doll inside A smaller problem
    The smallest doll, which does not open The base case

    Divide and conquer¶

    Recursion often follows the divide-and-conquer plan: (1) break a big problem into smaller ones, (2) solve each smaller one the same way, and (3) combine the results. Tree traversal, searching algorithms, and sorting algorithms such as Merge Sort and Quick Sort work this way.

    6.19 Example: factorial using recursion¶

    The factorial of a whole number n (written n!) is n x (n-1) x (n-2) x ... x 2 x 1, and 0! is defined as 1. It can also be written in terms of itself:

    Case Definition
    n = 0 or n = 1 fact(n) = 1
    n > 1 fact(n) = n x fact(n - 1)

    So finding fact(n) becomes the smaller problem of finding fact(n - 1). That makes it a natural fit for recursion.

    Working out 5! by hand:

    5! = 5 * (4 * (3 * (2 * 1)))
   = 5 * (4 * (3 * 2))
   = 5 * (4 * 6)
   = 5 * 24
   = 120

    Why check both n == 0 and n == 1? Maths books often use only 0! = 1 as the base case. The script also stops at 1, which saves one call, and still handles 0 correctly. What matters is that the base case is always reached. A recursion that could skip past it (for example, starting from a negative number) would never stop.

    Example 15: Factorial with the steps printed¶

    What it does: asks for a whole number, works out its factorial recursively, and prints each step on the way down and on the way back up.

    How to run it: type a whole number such as 5 and press Enter. The saved output shows a run with 10.

    How it does it:

    1. Going down: each call prints "Computing: n x factorial(n-1)" and then calls itself with n - 1. Nothing is multiplied yet; each call waits for the answer from the one below it.
    2. The base case: factorial(1) (or factorial(0)) returns 1 straight away.
    3. Coming back up: each waiting call now gets its answer, multiplies it by its own n, prints "Returning: n! = ...", and passes the result up.

    Why: the printed steps let you watch the calls pile up and then "unwind".

    Learning points:

    • Each waiting call is kept on the call stack with its own n. The calls unwind in the reverse order to the one in which they were made.
    • There is no input check. A negative number would never reach the base case and would end in a RecursionError, so do not try one here.

    print(f"Returning: {n}! = {result}")
    return result  # Return the computed factorial value to the caller

    6.21 Recursion example: Tower of Hanoi¶

    The puzzle has 3 rods and a number of disks of different sizes. At the start, all the disks are on one rod (the source), the biggest at the bottom and the smallest at the top. The goal is to move the whole stack to another rod (the target), using the third rod (the auxiliary) to help, and obeying these rules:

    1. Move only one disk at a time.
    2. Only the top disk of a stack can be moved.
    3. A disk may never be placed on top of a smaller disk.

    The recursive idea. To move n disks from the source to the target:

    1. Move the top n - 1 disks from the source to the auxiliary rod.
    2. Move the biggest disk (disk n) from the source to the target.
    3. Move the n - 1 disks from the auxiliary rod to the target.

    Steps 1 and 3 are smaller versions of the same puzzle, so the function calls itself for them. The base case is a single disk, which is just moved.

    How many moves? If M(n) is the number of moves for n disks, then M(n) = 2 x M(n - 1) + 1, because you move n - 1 disks twice and the big disk once. This works out to M(n) = 2ⁿ - 1. For 3 disks that is 7 moves; for 5 disks, 31; for 64 disks, more than 18 billion billion.

    How the script stores the rods. Each rod is a list. A disk is a number: n is the biggest and 1 the smallest. The left end of a list is the bottom of the rod, and the right end is the top. So the start is A = [3, 2, 1], B = [], C = []. Moving a disk means pop() from one list and append() to another.

    Example 17: Tower of Hanoi with 3 disks¶

    What it does: solves the puzzle for 3 disks and prints the rods after every move. It takes 7 moves.

    How it does it:

    Function Job
    print_towers(towers) Prints the three lists and a dividing line
    move_disk(towers, source, target, move_counter) Pops the top disk from one rod, appends it to another, adds 1 to the count, and prints the new state
    hanoi_recursive(n, source, target, auxiliary, towers, move_counter) The recursive plan: base case (n == 1), or the three steps above

    The rods are kept in a dictionary, towers = {"A": [...], "B": [], "C": []}, so a rod can be reached by its letter.

    Learning points:

    • Why is the counter a list, move_counter = [0]? A function cannot re-assign a plain integer that belongs to its caller (Section 6.1). But it can change the contents of a list it was given. So move_counter[0] += 1 updates the one shared count. (This is the same trick as the list-based counter in Chapter 5.)
    • Notice how the roles of the rods swap in the recursive calls: in step 1 the target and auxiliary are swapped; in step 3 the source and auxiliary are swapped.
    • Change num_disks to 4 and check that it takes 2⁴ - 1 = 15 moves.

    # Tower of Hanoi using three lists representing towers A, B, C. Each list acts
# like a stack. In the list leftmost item is at bottom (Biggest) and rightmost
# is at top (Smallest). The script also counts and displays move numbers.

def print_towers(towers):
    """Display the current state of all three towers."""
    print(f"A: {towers['A']}   B: {towers['B']}   C: {towers['C']}")
    print("-" * 40)

def move_disk(towers, source, target, move_counter):
    # Move top disk from one tower to another also increment the move counter

    disk = towers[source].pop()     # Remove top disk from source
    towers[target].append(disk)     # Place disk on target

    move_counter[0] += 1            # Increment move count

    print(f"Move {move_counter[0]}: disk from {source} → {target}")
    print_towers(towers)

def hanoi_recursive(n, source, target, auxiliary, towers, move_counter):
    """
    Recursive solution to Tower of Hanoi.

    n         -&gt; number of disks
    source    -&gt; source tower (A/B/C)
    target    -&gt; target tower (A/B/C)
    auxiliary -&gt; auxiliary tower (A/B/C)
    towers    -&gt; dictionary storing the towers
    move_counter -&gt; list used to track number of moves
    """

    # -------- Base Case --------
    if n == 1:
        move_disk(towers, source, target, move_counter)
        return

    # -------- Recursive Case --------

    # Step 1: Move n-1 disks from source → auxiliary
    hanoi_recursive(n - 1, source, auxiliary, target, towers, move_counter)

    # Step 2: Move largest disk from source → target
    move_disk(towers, source, target, move_counter)

    # Step 3: Move n-1 disks from auxiliary → target
    hanoi_recursive(n - 1, auxiliary, target, source, towers, move_counter)

    6.23 Memoisation¶

    Memoisation is a way to speed up a function:

    1. The first time the function works out a value, it stores (caches) the result.
    2. When it is asked for the same value again, it simply returns the stored result.
    3. This avoids repeating long calculations.

    It works best for recursive functions where the same sub-problems come up again and again, like Fibonacci. Without memoisation, fib(5) works out fib(3) twice and fib(2) three times (see the tree in Example 16). With it, each value is worked out only once.

    Example 18: Fibonacci with memoisation¶

    What it does: works out Fibonacci numbers 10, 15 and 20, then prints the whole cache.

    How it does it:

    1. memo = {0: 0, 1: 1} is a dictionary that already holds the two base cases.
    2. Step 1: if n is already a key in memo, return the stored value at once.
    3. Step 2: otherwise, work out fib_memo(n - 1) and fib_memo(n - 2).
    4. Step 3: store the result in memo[n].
    5. Step 4: return it.

    Why: fib_memo(20) needs only about 20 new calculations. The plain recursive version would need more than 20,000 calls.

    Learning points:

    • The cache lives outside the function, so it survives from one call to the next. After fib_memo(10), the call fib_memo(15) reuses values 0 to 10 and only works out 11 to 15.
    • The printed cache shows every value that was stored, from 0 up to 20.
    • Python can do this for you with the functools.lru_cache decorator. See "Beyond the Book", Extra 2.

    # Fibonacci using Memoization (Optimized Recursion)

memo = {0: 0, 1: 1}
# memo is a dictionary that will store previously computed Fibonacci values.
# It starts with the base cases: F(0) = 0 and F(1) = 1. As the recursive
# function computes new Fibonacci numbers, it will add them to this dictionary,
# allowing for fast retrieval in future calls.

def fib_memo(n):
    # Returns the nth Fibonacci number using memoization to optimize recursion.
    # It checks if value is already computed &amp; stored in the memo dictionary.
    # If it is, it returns that value immediately. If not, it computes it
    # recursively, stores the result in the memo, and then returns it.

    # -------- Step 1: Check if value already exists in cache --------
    # If yes, return it immediately (very fast)
    if n in memo:
        return memo[n]

    # -------- Step 2: Otherwise compute recursively --------
    # Break the problem into two smaller Fibonacci problems
    fib_n_minus_1 = fib_memo(n - 1)
    fib_n_minus_2 = fib_memo(n - 2)

    result = fib_n_minus_1 + fib_n_minus_2

    # -------- Step 3: Store the result in the cache --------
    memo[n] = result

    # -------- Step 4: Return the computed value --------
    return result

    6.25 Generator functions (basic concepts)¶

    How a normal function works: when it is called, (1) it starts running, (2) it runs until it reaches return, (3) it hands back the result, and (4) all its local variables are destroyed. Calling it again starts from the beginning.

    How a generator function works: it produces a series of values, one at a time. It uses the keyword yield instead of return. At each yield:

    1. the value is handed back to the caller,
    2. the function's state (its local variables and where it had got to) is saved,
    3. the function pauses, and
    4. when the next value is asked for, it carries on from exactly the same point.

    When the function reaches its end, it raises StopIteration, which tells the caller that there are no more values.

    Normal function Generator function
    Keyword return yield
    Runs Once, from start to end Pauses and resumes
    Gives back One value Many values, one at a time
    Local variables after it hands back a value Lost Kept

    Generator rule: if a function contains yield anywhere, Python treats it as a generator function. Calling it does not run its body. It returns a generator object, and the body only runs when you ask for values.

    Example 20: A simple generator¶

    What it does: creates a generator that yields 1, 2 and 3, and gets each value with next().

    How it does it:

    1. gen = simple_generator() creates the generator object. Nothing in the body has run yet.
    2. The first next(gen) runs the body up to yield 1, hands back 1 and pauses.
    3. The second next(gen) carries on to yield 2.
    4. The third next(gen) carries on to yield 3.

    Learning point: a fourth next(gen) would raise StopIteration, because the body has ended. Try it in a new cell.

    # Simple generator example

def simple_generator():
    yield 1  # yield used to produce a value and pause function's execution
    yield 2  # yield produces the next value when generator is resumed
    yield 3  # yield produces final value after which generator is exhausted

# Create a generator object
gen = simple_generator()

    Example 22: An infinite counter¶

    What it does: creates a generator that counts 1, 2, 3, ... for ever, and takes the first three values.

    How: while True: never ends, but that is fine: at each yield the function pauses, and it only moves on when another value is asked for.

    Why generators are useful:

    1. They produce values one at a time, only when needed.
    2. They save memory: no list of all the values is ever built.

        num += 1

    6.26 Functions are "first-class" objects¶

    In Python, a function is a thing (an object), just like a list or a string. You can store it in a variable, pass it to another function, and return it from a function.

    The bracket rule:

    • bark() with brackets means: run the function now.
    • bark without brackets means: the function itself (the object).

    6.27 The manual decorator: using closures to "wrap" code¶

    A decorator is like gift wrapping. The box (your function) stays the same, but the wrapping adds something extra around it.

    Suppose you want bark() to print "START" before it barks and "END" afterwards. One way is to edit the function:

    Original function Modified function
    def bark():
    print("Woof!")    		 def bark():
    print("START")
    print("Woof!")
    print("END")
    Output: Woof! Output: START, Woof!, END

    But that changes the original code. A decorator adds the same behaviour without touching the original function.

    How it works: a decorator is a closure (Chapter 5) that takes a function as its input.

    Part Job
    The outer function, my_decorator(func) The "factory". It receives the function to be wrapped
    The inner function, wrapper() The "wrapping". It holds the extra code and the call to the original function
    Definition, not execution Python only stores a function when it reads def. The body runs later, when called
    return wrapper Hands back the inner function itself, without brackets, so it can be called later

    Example 24: Decorating bark() by hand¶

    What it does: wraps bark() so that it prints a START line, then Woof!, then an END line.

    How it does it:

    Step Line What Python does Does the original bark() run?
    1 def my_decorator(...) Stores the factory No
    2 def bark(): ... Stores the original bark No
    3 bark = my_decorator(bark) Passes the original to the factory. The name bark now points to wrapper No, it is only packaged
    4 bark() Runs wrapper, which prints START, calls the original bark (Woof!), prints END and returns 'Barking Done' Yes, from inside the wrapper

    Learning points:

    • After step 3, the name bark refers to the wrapper. The original function is still alive, stored inside the wrapper as func.
    • The notebook also shows 'Barking Done' under the printed lines. That is the value returned by the last line, bark(), which a notebook displays automatically. In a .py script it would not appear.

    def my_decorator(func):
    # The Decorator Factory: Accepts a function object as 'func'.

    def wrapper():
        # --- PHASE 1: Pre-Execution ---
        print("--- [START] Logic added by Decorator ---")

        # --- PHASE 2: Execution &amp; Capture ---
        # We run the original logic and save whatever it returns.
        result = func()

        # --- PHASE 3: Post-Execution ---
        print("--- [END] Logic added by Decorator ---")

        # --- PHASE 4: Return ---
        # We hand the result back to the line that called bark().
        return result

    return wrapper # return wrapper function object not result of calling it

    # The original function.
    print("Woof!")
    return "Barking Done"

# but it is a common pattern in Python for applying decorators manually.
bark = my_decorator(bark)

# --- STEP 2: Execution ---
# We call bark() directly.
bark()

    6.29 Handling arguments: the unpackers¶

    The wrapper stands between the caller and the original function. If the original function takes arguments, the wrapper must accept them and pass them on. To work with any function, whatever its arguments, the wrapper uses *args and **kwargs:

    Tool Collects Inside the wrapper it is Best for
    *args arguments passed by position, such as "Bruno" a tuple, e.g. ('Bruno',) simple lists of values
    **kwargs arguments passed by name, such as food="Chicken" a dictionary, e.g. {'food': 'Chicken'} clearly labelled data

    The pass-through:

    • Packing: in def wrapper(*args, **kwargs):, the stars collect the arguments of the call into a tuple and a dictionary.
    • Unpacking: in func(*args, **kwargs), the stars spread them out again, so the original function receives exactly what the caller sent.

    Without this, the wrapper would only work for functions with exactly the arguments it was written for.

    Example 26: A decorator that checks a pet's food¶

    What it does: wraps feed_pet() with a checker. Before feeding, it warns if the food is unhealthy for pets.

    How it does it:

    1. feed_pet("Tiger", food="Chicken") actually calls wrapper. "Tiger" goes into args, and food="Chicken" goes into kwargs.
    2. kwargs.get("food", "Unknown food") reads the food safely. If no food was given by keyword, it uses "Unknown food" instead of raising an error.
    3. If the food is in unhealthy_foods, a warning is printed; otherwise an info message.
    4. func(*args, **kwargs) unpacks everything and runs the original feed_pet().
    Call args kwargs Check Printed
    feed_pet("Tiger", food="Chicken") ('Tiger',) {'food': 'Chicken'} safe [INFO] Chicken is safe. Proceeding... then Feeding Tiger some Chicken.
    feed_pet("Kitty", food="Chocolate") ('Kitty',) {'food': 'Chocolate'} unhealthy [WARNING] Chocolate is BAD for pets! then Feeding Kitty some Chocolate.

    Learning points:

    • The wrapper only warns: feed_pet() still runs even for bad food. To stop it, the wrapper could return early without calling func.
    • Try feed_pet("Bruno"). The food is not in kwargs, so the check says "Unknown food is safe", but feed_pet() itself uses its default and prints "Feeding Bruno some Bread." The wrapper cannot see the default of the original function. Try also feed_pet("Bruno", "Cakes"): passed by position, the food is missed by the check.

    def food_checker(func):
    """
    A decorator that inspects function arguments (*args, **kwargs).
    """
    def wrapper(*args, **kwargs):
        # 1. Identify the food.
        # Since we are passing 'name' by position, args[0] is the name.
        # Since we are passing 'food' by keyword, it is in kwargs["food"].
        # Safely get 'food' from kwargs, default to "Unknown food" if not given
        # This prevents an error even if "food" is not provided.
        food = kwargs.get("food", "Unknown food")

        # 2. Perform the 'Check' logic
        unhealthy_foods = ["Chocolate", "Cakes", "Onions"]

        if food in unhealthy_foods:
            print(f"[WARNING] {food} is BAD for pets!")
        else:
            print(f"[INFO] {food} is safe. Proceeding...")

        # 3. Execute the original function
        return func(*args, **kwargs)

    return wrapper

@food_checker
def feed_pet(name, food="Bread"):
    print(f"Feeding {name} some {food}.")

# --- TEST CASES ---
# 'Tiger' goes to *args | food='Chicken' goes to **kwargs
feed_pet("Tiger", food="Chicken")  # Good food

# 'Kitty' goes to *args | food='Chocolate' goes to **kwargs
feed_pet("Kitty", food="Chocolate")  # Bad food

[WARNING] Chocolate is BAD for pets!

    6.30 How the Python interpreter searches for modules¶

    When Python meets import module_name, it must find the module's file. The search goes like this:

    1. Already loaded? A module is loaded only once per session. If it has already been imported, Python reuses it and does not run its code again.
    2. Search sys.path. Otherwise, Python looks through the folders listed in sys.path, in order, and uses the first match. The list is built when Python starts, and usually contains:
      • the folder of the script being run (in a notebook, the current working folder),
      • the folders in the PYTHONPATH environment variable, if it is set (a user-defined list of extra folders, which works like the system PATH),
      • the folders of Python's standard library, and
      • the site-packages folder, where pip installs packages.
    3. Not found anywhere? Python raises ModuleNotFoundError: No module named 'module_name'.

    (Chapter 2 has a more detailed, 13-step version of this process.)

    Extra 1: Factorial by recursion and by a loop¶

    Section 6.22 compared recursion with iteration. Both functions below give the same answer. The loop version uses no extra function calls, so it has no depth limit.

    import sys

def fact_recursive(n):
    return 1 if n &lt;= 1 else n * fact_recursive(n - 1)

def fact_loop(n):
    result = 1
    for k in range(2, n + 1):
        result = result * k
    return result

print(fact_recursive(10), fact_loop(10))   # 3628800 3628800
print("Recursion limit:", sys.getrecursionlimit())

    Extra 2: Memoisation for free with functools.lru_cache¶

    Python's standard library can add a cache to any function. @lru_cache is a decorator (Section 6.28): it wraps the function and remembers each result. With it, the plain recursive Fibonacci of Example 16 becomes fast.

    maxsize=None means "keep every result". fib.cache_info() shows how many times the cache was used (hits) and how many values had to be worked out (misses).

    from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n &lt; 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(80))            # instant, even though it is plain recursion
print(fib.cache_info())

    Extra 3: reduce(), sorted() with a lambda key¶

    Two more higher-order functions:

    • functools.reduce(function, iterable) combines all the items into one value, two at a time. reduce(lambda a, b: a * b, [1, 2, 3, 4, 5]) works out ((((1 x 2) x 3) x 4) x 5) = 120.

print(sorted(words, key=lambda w: len(w)))           # shortest first
